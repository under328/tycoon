# 网络协议 v1.2（ENet / Godot 高层 multiplayer）

> 传输：`ENetMultiplayerPeer`，全部走 reliable 通道（回合制，消息小且稀）。
> 消息定义代码：`src/protocol/msg.gd`；可见信息裁剪：`src/protocol/view.gd`；
> 两端共用的统一网络节点：`src/protocol/net_node.gd`（RPC 配置对称）。
> payload 一律为 Dictionary，字段名蛇形命名；服务器对每个动作做 schema + 规则双重校验。
> v1.1 变更：hello 携带 client_id；新增 room_settings / emoji / chat / stats；
> game_view 附带 turn_seat；game_end 附带 identities/last_points/stats。

## 1. 连接与握手

```
客户端 → 服务器   hello { ver:int, session_token:String(可空), client_id:String, skin_id:String }
服务器 → 客户端   welcome { seat:int(-1=未入座), protocol_ok:bool }
                  或 kicked { reason:String }   # 版本不符: reason="version"
```

- `ver` 不匹配 → 拒绝并提示更新（`kicked/version`，客户端展示下载地址）。
- 带 `session_token` 重连 → 服务器尝试恢复座位（见 §4）。
- `client_id` 为游客身份（客户端首启生成并持久化），用于战绩归属。
- `skin_id` 为玩家装备的装饰皮肤（仅装饰，不参与规则判定）。

## 2. 大厅与房间

```
C→S  room_quick  { name, rules?, client_id }   # 快速匹配: 入等待中的公开房, 无则建新房
C→S  room_create { name, rules?, client_id }   # 建私房, 返回 6 位房间码
C→S  room_join   { name, code, client_id }
C→S  room_leave  {}
C→S  room_kick   { seat:int }                  # 仅房主
C→S  bot_fill    {}                            # 空位补 AI (仅房主)
C→S  room_start  {}                            # 仅房主, 空位自动补 AI
C→S  room_settings { rules }                   # 仅房主, 仅开局前
C→S  emoji       { id:int }                    # 快捷表情, 服务端限速 500ms
C→S  chat        { text:String ≤80 }           # 房内文本聊天, 服务端限速 500ms
C→S  stats       {}                            # 查询本人战绩

S→C  room_state { room_code, host_seat, settings,
                  players:[{seat, empty, name, is_bot, online}],
                  session_token(仅本人) }
S→C  stats      { your:entry }                # entry: {name, matches, wins, total_points}
S→C  s_emoji    { seat:int, id:int }          # 表情广播
S→C  s_chat     { seat:int, text:String }     # 聊天广播
S→C  kicked     { reason }                    # "version"/"host"/"full"/"in_game"...
S→C  error      { code, msg }
```

## 3. 对局（服务器权威）

```
C→S  game_play   { cards:[int] }
C→S  exchange_return { cards:[int] }  # 换牌阶段返还牌(位置与 game_play 类似)
C→S  exchange_return { cards:[int] }           # 换牌阶段: 接收者返还 n 张
C→S  game_pass   {}
S→C  game_view   { view:Dictionary, turn_seat:int }  # 按座位私发, 结构见 §5
S→C  game_turn   { seat:int }                # (冗余事件, UI 可只用 view)
S→C  game_played { seat:int, combo:{type,key,len,cards}, remain:int, eight_cut:bool }
S→C  game_cleared{ seat:int }                # 清桌
S→C  revolution  { on:bool }
S→C  round_end   { identities:[int], last_points:[int], scores:[int] }
S→C  exchange    { picks:[{from, to, cards, count}] }  # 交换过场(交牌自动, 返还待选)
S→C  game_end    { scores:[int], identities:[int], last_points:[int],
                   stats:{ seat:entry } }   # stats=人类玩家最新战绩(记录后快照)
S→C  error       { code:String, msg:String }
```

## 3.5 格斗对战（房间 mode="fight"，1v1 + 观战）

- 房间 `settings.mode = "fight"` 时开局：**前 2 个座位为格斗者**（仅 1 人时
  2 号位自动补 AI），**3/4 号位玩家自动成为观战者**。
- 两人从服务器同一候选池(10 张)各选 5 张 → 派生属性 → 回合制互殴；
  先手 = 牌型层级更强一方(平级先座者)。规则见 `src/rules/fight/fight_pvp.gd`。
- 观战者全程收到相同战斗视图但不可操作；格斗者离线由 AI 托管。

```
C→S  fight_pick  { cards:[int ×5] }   # 选牌阶段提交(仅格斗者, 先到先锁)
C→S  fight_act   { action:"attack"|"skill"|"defend" }  # 仅当前回合格斗者
S→C  fight_state { view:Dictionary, events:[...] }   # 全房广播(按座位裁剪)
```

`fight_state.view`：
```
{
  phase: "pick"|"battle"|"over",
  my_seat: int, fighters: [int, int], spectator: bool,
  names: {seat: String},
  picks_done: {seat: bool},
  # pick 阶段:
  candidates: [int ×10], my_pick: [int](仅本人, 未选为空),
  # battle/over 阶段(装备公开):
  hands: {seat: [int ×5]}, combo: {seat: {name, desc, tier}},
  skill_cd: {seat: int}, skill_kind: {seat: "fire"|"frost"|"light"},
  stats_brief: {seat: {atk, def, mres, skill}},
  hp: {seat: int}, max_hp: {seat: int},
  turn: int, my_turn: bool, turn_seconds: int,
  round_no: int, winner: int(-1=未定), log: [String],
}
```
`events` 为本回合飘字事件：`{who, target, kind: dmg|crit|skill|heal|defend|chill, v}`。

## 4. 断线重连与托管

- 进房时服务器随 `room_state` 下发 `session_token`（客户端持久化于 `user://`）。
- 掉线：服务器保留座位至**本场对局结束**（宽限），立即由 AI 托管；期间重连
  （`hello` + token）→ 服务器重发 `room_state` + 完整 `game_view`，玩家夺回座位。
- 客户端每 2s 自动重试连接；恢复失败超过 60s 提示回大厅。
- 对局结束时的离线座位自动释放，可被新玩家加入。
- 所有回合等待以服务器计时器为准（`game_turn`/view 携带，默认 20s），到点自动执行托管动作。

## 5. `game_view` 结构（按座位私发 — 防作弊核心）

```
{
  phase: "wait"|"deal"|"exchange"|"play"|"round_end"|"game_end",
  round: int, rounds_total: int, rules: Dictionary,
  my_seat: int,
  hand: [int],                      # ★ 仅本人手牌(已排序); 其他人不出现
  counts: [int ×4],                 # 各家剩余牌数
  finished: [int],                  # 已出完座位顺序
  turn: int, lead: combo?, field: [ {seat, combo} ],
  revolution: bool,
  scores: [int ×4], identities: [int], last_points: [int],
  exchange: [ {from, to, cards, count} ],
  exchange_return: {seat:int, n:int, to:int} | {},  # 换牌阶段当前待返还者(空=无)
  must_include: int                 # 首局首手须包含的牌(♦3=2), 无则 -1
}
```

不变式（单测覆盖）：任何 view 中除 `hand` 外不得出现其他玩家的具体牌 id。

## 6. 版本策略与健康检查

- `msg.gd` 导出 `PROTOCOL_VERSION`；服务器与客户端不一致即拒绝（`kicked/version`），
  客户端提示前往下载页（地址常量 `GameSettings.DOWNLOAD_URL`）。
- 服务器另开 TCP `端口+1` 提供 HTTP 健康检查：`curl http://<ip>:24566/` → JSON 状态。
- 服务器每 60s 打印一行 `rooms/players/uptime` 状态日志。
